# Contributing to SOLIAS

Contributions are welcome when they clarify application of the standard, document implementation experience, add worked examples, or develop compatible domain guidance. The governance plan distinguishes routine clarification from revisions that would alter the common classification.

## Before opening a pull request

Choose the issue form that best matches the proposal:

- **Clarification request** for interpretation of an existing definition, checklist item, schema field, or example;
- **Implementation problem** for difficulties encountered in study design, writing, review, evidence synthesis, or machine-readable reporting;
- **Domain profile proposal** for domain-specific examples, measures, safeguards, or implementation guidance; or
- **Core classification change** for revisions to the evidence-level ontology, `(E, C, G)` representation, or another part of the common classification.

A useful issue identifies the affected material and provides the relevant rationale, evidence, or implementation experience.

## Pull requests

Documentation corrections, worked examples, schema clarifications, and compatible implementation guidance may be proposed through pull requests. A proposal that changes the evidence-level ontology or `(E, C, G)` representation should begin with a core-classification issue so that compatibility and versioning can be considered before the revision is prepared.

## Domain-specific material

Domain-specific guidance is organized as a profile that preserves the six evidence levels and `(E, C, G)`. A profile may add measures, safeguards, examples, or implementation guidance appropriate to the domain.
